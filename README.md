# Работа Бандита — Railway + PostgreSQL

Эта версия подготовлена для PostgreSQL в Railway.

## Что изменено

- SQLite полностью убран из подключения приложения.
- Бот использует `DATABASE_URL` Railway или `PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE`.
- Таблицы создаются автоматически из `schema.sql` при запуске.
- Существующие таблицы PostgreSQL не удаляются благодаря `CREATE TABLE IF NOT EXISTS`.
- Добавлены PostgreSQL-совместимые `ON CONFLICT`, `GREATEST`, `LEAST` и запросы статистики.
- Активные чаты, активность пользователей, VIP-задачи, события, админские логи и рассылки сохраняются в PostgreSQL.
- В `/чаты` показывается название, количество участников (если Telegram разрешает получить его) и возможность отправки.
- Сообщения ботов не учитываются в активности.
- Повторная выдача того же временного VIP продлевает срок.
- Исправлен вывод переносов строк в VIP и приветственной информации.
- Токен бота больше не хранится в исходниках.

## Railway

PostgreSQL Railway автоматически предоставляет приложению `DATABASE_URL` и переменные `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`.

В Variables самого сервиса бота нужно добавить:

- `BOT_TOKEN` — токен бота.

`MAIN_ADMIN_ID` уже указан в `config.php`.

После подключения PostgreSQL ничего вручную создавать во вкладке Data не нужно: при первом запросе бот создаст таблицы сам.

## Важно

Если старый `bot.sqlite` был удалён и отдельной копии нет, старые данные игроков автоматически восстановить нельзя. Новая PostgreSQL-база начинается пустой.

Если токен бота когда-либо публиковался в GitHub или передавался посторонним, его безопаснее перевыпустить через BotFather и записать новый токен в Railway Variables.
